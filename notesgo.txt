package main

import (
	"fmt"
	"net/http"
)

func logger(next http.HandlerFunc) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {

		if r.Method != "GET" {
			w.Header().Set("Content-Type", "application/json")
			w.Write([]byte("Method not allowed"))
			fmt.Println("LOG : Not Allowed Method", r.Method, "On Path:", r.URL.Path)
			return
		}

		fmt.Println("LOG : Request Received with Path:", r.URL.Path, "and Method:", r.Method)

		next(w, r)

		fmt.Println("Request Sent From Logger")
	}
}

func authorizer(next http.HandlerFunc) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		fmt.Println("Entered Authorize Middleware")
		token := r.Header.Get("X-API-KEY")
		if token != "secret" {
			w.Header().Set("Content-Type", "application/json")
			w.Write([]byte("Unauthorized"))
			fmt.Println("Exiting Authorized Middleware Because of Missing Header")
			return
		}
		next(w, r)

		fmt.Println("Exiting Authorized Middleware Cleanly")
	}
}

func hello(w http.ResponseWriter, r *http.Request) {
	fmt.Fprintln(w, "Hello to authorized user from go backend")
}

func main() {
	http.HandleFunc("/hello", logger(authorizer(hello)))

	fmt.Println("Running and listening on port 8080")
	http.ListenAndServe(":8080", nil)
}

Nice — you’ve reached the point where Gin starts feeling “real” 😄
That line is Gin’s **default logger output**, and yeah, the colors come from its built-in logger.

Let’s decode one line:

```
[GIN] 2026/04/08 - 17:57:18 | 200 | 55.693µs | ::1 | GET "/"
```

---

## 🧩 Breakdown of each component

### 🔹 `[GIN]`

* Just a prefix showing the log is from **Gin framework**

---

### 🔹 `2026/04/08 - 17:57:18`

* 📅 Date and time of the request

---

### 🔹 `200`

* ✅ HTTP status code
* `200` = OK (success)
* `404` = Not Found (your second log)

---

### 🔹 `55.693µs`

* ⏱️ Time taken to handle the request
* `µs` = microseconds (very fast)

---

### 🔹 `::1`

* 🌐 Client IP address
* `::1` = IPv6 version of `localhost` (same as `127.0.0.1`)

---

### 🔹 `GET`

* 📡 HTTP method
* Could be `GET`, `POST`, `PUT`, `DELETE`, etc.

---

### 🔹 `"/"`

* 📍 Route (endpoint) accessed

---

## 🔴 Second line example

```
[GIN] 2026/04/08 - 17:58:09 | 404 | 445ns | ::1 | POST "/"
```

* `404` → route not found
* `POST "/"` → you didn’t define a POST handler for `/`
* `445ns` → super fast rejection

---

## 🎨 Why is it colorful?

Gin uses a logger middleware:

```go
gin.Default()
```

This includes:

* Logger (colored output)
* Recovery (prevents crashes)

### 🌈 Color meaning (important)

* 🟢 **Green** → 2xx (success)
* 🟡 **Yellow** → 3xx (redirect)
* 🔴 **Red** → 4xx / 5xx (errors)

---

## ⚙️ Where does this come from?

This is from:

```go
r := gin.Default()
```

If you instead use:

```go
r := gin.New()
```

👉 No logs, no colors (unless you add middleware manually)

Basic Function of Backend Using Gin
search para, query para, struct input, get, post etc

package main

import (
	"fmt"

	"github.com/gin-gonic/gin"
)

type User struct {
	Name string `json:"name"`
	Age  int    `json:"age"`
}

func Logger() gin.HandlerFunc{
	return func(ctx *gin.Context) {
		fmt.Println("Request received")

		ctx.Next()

		fmt.Println("Response sent")
	}
}

func main() {
	r := gin.Default()

	r.Use(Logger())
	r.GET("/", func(c *gin.Context) {
		c.JSON(200, gin.H{
			"message": "Hello From Go Backend Using Gin",
		})
	})

	r.POST("/user", func(c *gin.Context) {
		var user User

		c.BindJSON(&user)

		c.JSON(200, gin.H{
			"message": "body received successfully",
			"name":    user.Name,
			"age":     user.Age,
		})
	})

	r.GET("/user/:id", func(ctx *gin.Context) {
		id := ctx.Param("id")
		ctx.JSON(200, gin.H{
			"id": id,
		})
	})

	r.GET("/search", func(ctx *gin.Context) {
		name := ctx.Query("name")

		ctx.JSON(200,gin.H{
			"name":name,
		})
	})

	r.Run(":8080")
}

> “Where exactly should I check errors in a Go API?”

Let’s make this **very clear + structured** so you can follow it in every project.

---

# 🧠 1. Golden Rule

👉 In Go:

> **Any function that returns `error` → MUST be checked**

---

# ⚙️ 2. Common Places You MUST Handle Errors (Gin + Backend)

---

# 🔥 1. Request Parsing (VERY COMMON)

```go
err := c.BindJSON(&data)
```

👉 Possible errors:

* invalid JSON
* wrong data types

---

## ✅ Always check:

```go
if err != nil {
    c.JSON(400, gin.H{"error": "Invalid JSON"})
    return
}
```

---

# 🔥 2. Path Parameters

```go
id := c.Param("id")
```

👉 Possible issue:

* empty or invalid ID

---

## ✅ Check:

```go
if id == "" {
    c.JSON(400, gin.H{"error": "ID required"})
    return
}
```

---

# 🔥 3. Query Parameters

```go
page := c.Query("page")
```

👉 Problem:

* missing or wrong type

---

## ✅ Example:

```go
if page == "" {
    c.JSON(400, gin.H{"error": "page required"})
    return
}
```

---

# 🔥 4. Type Conversion (VERY IMPORTANT)

```go
idInt, err := strconv.Atoi(id)
```

👉 Error if:

* id is not a number

---

## ✅ Always check:

```go
if err != nil {
    c.JSON(400, gin.H{"error": "Invalid ID"})
    return
}
```

---

# 🔥 5. Business Logic Errors

Example:

* product not found
* insufficient balance

---

## ✅ Example:

```go
if product == nil {
    c.JSON(404, gin.H{"error": "Not found"})
    return
}
```

---

# 🔥 6. Database Calls (VERY IMPORTANT – later)

```go
result, err := db.Query(...)
```

👉 Errors:

* connection failed
* query error

---

## ✅ Pattern:

```go
if err != nil {
    c.JSON(500, gin.H{"error": "Database error"})
    return
}
```

---

# 🔥 7. External APIs / Services

```go
resp, err := http.Get("...")
```

👉 Errors:

* network failure
* timeout

---

## ✅ Check:

```go
if err != nil {
    c.JSON(500, gin.H{"error": "Service unavailable"})
    return
}
```

---

# 🔥 8. Writing Response (rare but important)

```go
err := c.JSON(...)
```

👉 Usually safe, but in raw Go:

```go
_, err := w.Write(data)
```

---

# 🔥 9. Middleware Errors

Example:

* auth failure
* missing token

---

```go
token := c.GetHeader("Authorization")

if token == "" {
    c.JSON(401, gin.H{"error": "Unauthorized"})
    return
}
```

---

# 🧠 3. Full Checklist (MEMORIZE THIS)

Whenever you write API, check:

---

### ✅ Input Layer

* [ ] JSON parsing (`BindJSON`)
* [ ] Query params
* [ ] Path params
* [ ] Type conversion

---

### ✅ Validation Layer

* [ ] required fields
* [ ] empty values
* [ ] format (email, etc.)

---

### ✅ Business Layer

* [ ] resource exists
* [ ] logic errors

---

### ✅ External Layer

* [ ] DB errors
* [ ] API calls

---

### ✅ Auth Layer

* [ ] token exists
* [ ] token valid

---

# 🧠 4. Clean Pattern (VERY IMPORTANT)

Every API should follow:

```go
// 1. Parse
if err != nil → 400

// 2. Validate
if invalid → 400

// 3. Business logic
if not found → 404

// 4. Internal error
if failure → 500

// 5. Success
→ 200 / 201
```

---

# 🔥 5. Example (Complete Flow)

```go
r.POST("/products", func(c *gin.Context) {
    var product Product

    // 1. Parse
    if err := c.BindJSON(&product); err != nil {
        c.JSON(400, gin.H{"error": "Invalid JSON"})
        return
    }

    // 2. Validate
    if product.Name == "" {
        c.JSON(400, gin.H{"error": "Name required"})
        return
    }

    // 3. Business logic (dummy)
    if product.Name == "invalid" {
        c.JSON(400, gin.H{"error": "Invalid product"})
        return
    }

    // 4. Success
    c.JSON(201, gin.H{"message": "Created"})
})
```

# Go Visibility (Public vs Private)

## 🔹 Rule (Very Important)

In Go, visibility is controlled by **first letter capitalization**:

* **Capital letter → Public (exported)**
* **Small letter → Private (unexported)**

---

## 🔹 Functions

```go
func CreateProduct() {} // ✅ Public
func createProduct() {} // ❌ Private
```

* Public → accessible from other packages
* Private → only inside same package

---

## 🔹 Structs

```go
type Product struct {} // ✅ Public
type product struct {} // ❌ Private
```

---

## 🔹 Struct Fields (VERY IMPORTANT for JSON)

```go
type Product struct {
    Name  string  // ✅ Public (accessible + JSON works)
    price float64 // ❌ Private (ignored in JSON)
}
```

👉 If field starts with lowercase:

* Cannot access outside package
* `encoding/json` will NOT include it

---

## 🔹 JSON Behavior

```go
type Product struct {
    Name string  `json:"name"`  // ✅ included
    price float64 `json:"price"` // ❌ ignored
}
```

Output:

```json
{
  "name": "Laptop"
}
```

---

## 🔹 Mental Shortcut

* Capital = **visible everywhere**
* Small = **only inside package**

---

## 🔹 Summary

* Go has no `public/private` keywords
* First letter decides visibility
* Struct fields MUST be capitalized for APIs & JSON
